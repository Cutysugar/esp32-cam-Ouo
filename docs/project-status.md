## 状态更新（2026-09-29）：固件 v5 —— 双向保活 + OTA + /status

### 背景
两块板子分别接入同一红米 Mesh 网络的不同节点：
- 板 A：紧邻 **主路由**
- 板 B：紧邻 **Mesh 子路由**

### 发现的严重问题
板 B（连子路由）在**空闲十几秒后首次访问**时，HTTP 连接的 TCP 握手要等 **17 秒**；
而板 A（连主路由）随时访问都是 ~0.3s。连续访问时板 B 也很快。

### 定位过程与结论
1. 用 `curl -w` 拆解耗时：时间**全在 connect（TCP 握手）**，抓图本身正常 → 不是摄像头/固件逻辑问题
2. `/status` 显示 `wifi_ps=NONE`（已禁用 ESP32 省电）**仍复现** → **不是 ESP32 休眠**
3. 路由器后台确认板 B 连的是 **Mesh 子路由**，走**无线回程**：
   空闲时回程链路进入省电，跨节点流量需等待链路唤醒 → **根因是 Mesh 回程链路的休眠机制**

### 解决方案：双向保活心跳
固件 v5 每 3 秒发两个 UDP 小包：
1. → **网关**：保持上行（子路由 → 主路由）回程链路活跃
2. → **最近访问过它的客户端 IP**（自动学习）：刷新客户端 ARP 缓存，
   避免 ARP 条目过期后重新解析带来的延迟

### 实测效果
首次 `connect`：**17.4s → 0.02s**（与主路由下的板子持平）；
`total` 约 0.2~0.7s（跨回程传输略高于主路由下的 ~0.3s，属 Mesh 固有代价）。

### v5 固件新增能力

| 能力 | 说明 |
|------|------|
| 禁用 WiFi 省电 | `WiFi.setSleep(false)` |
| 双向保活心跳 | 解决上述 Mesh 子路由卡顿 |
| **OTA 无线升级** | 烧录一次后可通过 WiFi 更新固件，**不必再插 USB** |
| `/status` 诊断接口 | 复位原因 / 运行时长 / RSSI / 信道 / BSSID / 省电模式 / 保活计数 / OTA 主机名 |
| 断线自动重连 | — |

### 烧录 / 工具经验（重要）
1. **Arduino IDE 2.x 的「开发板 + 端口」是每个窗口独立保存的**。
   新窗口打开 .ino 时菜单里没有「分区方案 / 端口」，看起来像「检测不到板子」，
   其实只是该窗口还没选开发板 —— **先选开发板，分区方案和端口就都出现了**。
2. **分区方案必须选带 OTA 的**（`Minimal SPIFFS (1.9MB APP with OTA/...)`），
   否则 OTA 功能不可用。
3. ESP32-CAM 的 `GPIO0` 与摄像头 XCLK 共用。若上电瞬间 GPIO0 被拉低，
   芯片会进入**下载模式**（串口打印 `waiting for download`），需按 RST 才能正常运行。
