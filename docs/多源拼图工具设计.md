# 多源拼图视觉工具设计（2026-08-16）

## 目标
AI 从手机 agent 发起 tool 请求，后端拼一张「全家福」图（摄像头 ×2 + 电脑屏 + 手机屏，带标签），喂给 MiMo-2.5 识别，让 AI 一次看清：人在哪个房间、电脑在干嘛、手机在干嘛。

## 为什么拼一张而不是多图
多图每个都要过视觉编码器，费 token。拼一张带标签的大图最省，参照 AionsHome 哨兵模式的做法。

## 架构（已定案）
```
手机 agent（AI 发起 tool 请求）
  │ POST http://<家里PC>:8888/compose  （附上：手机自己的截屏）
  ▼
家里 PC 上的「拼图服务」（Python 小服务）
  ├─ 拉摄像头A/B 的图（LAN，http://<摄像头IP>/capture）
  ├─ 截自己屏幕（PIL ImageGrab）
  ├─ 收到手机 agent 附带的手机截屏
  ├─ 拼成一张带标签的大图
  └─ 返回拼接图 JPEG
  ▲
  │ 手机 agent 拿到拼接图
手机 agent ──POST 拼接图──▶ MiMo-2.5（走手机 agent 现有的图片接口）──▶ 识别结果
```

## 关键决策
- **调 MiMo 的是手机 agent（方案 B）**：因为手机 agent 已有现成 POST 图片接口，MiMo key 留在 agent 里
- 拼图服务只负责「采集 + 拼接 + 返回图」，不调模型
- 拼图服务放家里 PC（局域网），不放在 VPS（VPS 摸不到家里摄像头）
- 在家时整套流程纯局域网，不需要 VPS

## 拼接布局
```
┌─────────────────────────────┐
│  客厅摄像头  │  卧室摄像头     │  ← 摄像头层（标签烧在图上）
├─────────────────────────────┤
│  电脑屏幕                    │  ← 屏幕层
├─────────────────────────────┤
│  手机屏幕                    │  ← 屏幕层
└─────────────────────────────┘
```

## 三条铁律（来自 AionsHome 哨兵 prompt）
1. 标签必须烧进图里（黑条白字：客厅摄像头/卧室摄像头/电脑屏幕/手机屏幕），模型才分得清来源
2. 某个源离线 → 放占位块写「该源离线」，不能留空让模型瞎猜
3. 喂给 MiMo 的 prompt 要有分区规则：摄像头层判断「人在哪」，屏幕层只说明「在干嘛」，严禁用屏幕内容推断身体位置

## 降级场景
- 出门在外：拼图服务不可达 → 手机 agent 直接截自己的屏给 MiMo（只有手机屏）
- 摄像头掉线：拼图服务返回离线占位块
- PC 关机/黑屏：跳过 PC 层（或占位）

## 实施顺序
1. 先做「一块摄像头 + 电脑屏 + 手机屏」三源跑通（第二块摄像头还没买）
2. 第二块到手后加源，配 mDNS 主机名区分（esp32cam-a.local / esp32cam-b.local）
3. 前端/agent 侧工具定义 + MiMo 分区规则 prompt

## 待定
- 拼图服务的端口（暂定 8888）
- 手机 agent 的工具调用格式（等 agent 侧约定）
- 拼接图分辨率上限（建议总宽 1280~1600，平衡清晰度与 token）
